# Fix Session-Mode Filename Consistency — Implementation Plan

**Goal:** Remove eager filename resolution from `SessionMode.enter()` so the model invents its own filename on first Write; the host still normalizes (date-prefix, dedup), and the resolved path is persisted in wire records for compaction replay.

**Architecture:** `SessionMode.enter()` stops calling `resolveFilePathEagerly` — `_sessionModeFilePath` stays null after entry. A new method `resolveFilePathFromModelRequest` extracts a slug from the model's requested path basename on first Write, with content-heading/LLM fallback for unusable basenames. The resolved path is emitted in the `session_mode.enter` wire record (`path` field) and restored by `restoreEnter` on compaction replay.

**Tech Stack:** TypeScript, vitest, packages/agent-core

#### Step 2: Add `resolveFilePathFromModelRequest` method

In `packages/agent-core/src/agent/session-mode/index.ts`, insert after the public `resolveFilePathFromContent` method (after line 365) and before the private `llmSummarizeTitle` method (before line 367):

```ts
  /**
   * Resolve the session-mode file path from the model's first Write request.
   * Extracts a slug from the requested path basename, normalizes it with
   * a date prefix, deduplicates, and commits the path to the wire record.
   *
   * When the basename yields an unusable slug after sanitization (e.g. the
   * model requests `---.md`), falls back to content-based resolution via
   * {@link resolveFilePathFromContent}.
   */
  async resolveFilePathFromModelRequest(
    requestedPath: string,
    content: string,
  ): Promise<string> {
    if (this._sessionModeFilePath !== null) {
      return this._sessionModeFilePath;
    }

    const { dir } = await this.resolveSessionModeDirectory(this._kind);

    // Extract slug from the model's requested path basename.  basename()
    // strips any directory structure the model may have invented, so the
    // host remains in control of where the file actually lands.
    const base = basename(requestedPath);
    let slug = base.endsWith('.md') ? base.slice(0, -'.md'.length) : base;
    slug = slugifyTitle(slug);

    if (slug.length < 2) {
      // The model invented a path whose basename yields no usable slug.
      // Fall through to the existing content-based resolution (heading,
      // LLM summary, "untitled") which will set up the path + logRecord
      // internally.
      return this.resolveFilePathFromContent(content);
    }

    const datePrefix = formatDatePrefix(new Date());
    const stem = `${datePrefix}-${slug}`;
    const finalStem = await this.findUniqueStemInDir(dir, stem);
    const path = join(dir, `${finalStem}.md`);

    this._sessionModeFilePath = path;
    this.agent.emitStatusUpdated();

    this.agent.records.logRecord({
      type: 'session_mode.enter',
      id: this._sessionModeId!,
      kind: this._kind,
      path,
    });

    return path;
  }
```

Note: `resolveFilePathFromContent` also sets `_sessionModeFilePath` and emits status — that covers the fallback case. But it does NOT currently log a `session_mode.enter` record with `path`. We need to add that to `resolveFilePathFromContent` as well so the fallback path is also persisted.
