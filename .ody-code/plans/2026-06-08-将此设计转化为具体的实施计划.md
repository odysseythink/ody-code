# 浏览器控制替代方案实施计划：从 Chrome DevTools MCP 到 Agent-Core 原生 Browser Agent

**Goal:** 将浏览器控制能力从 vendored `chrome-devtools` MCP server 下沉为 `packages/agent-core` 的原生内置工具，提供 `BrowserBrowse`/`BrowserExtract`/`BrowserAct` 高阶意图工具 + 原子 fallback 工具族，实现按 URL host 的 session-level 权限授权，默认禁用旧 MCP 但保留 `legacyMcpEnabled` 回退开关。

**Architecture:** 在 `packages/agent-core` 中新增 `BrowserConnectionManager`（Puppeteer CDP 连接 + 自动 launch 回退），由 `Agent` 实例持有并在 `Session.close()` 中清理；浏览器工具族在 `ToolManager.initializeBuiltinTools()` 中条件注册，所有工具统一返回 `Browser*(host)` 格式的 `approvalRule` 与 `matchesRule`；`BrowserHostPermissionPolicy` 插入权限策略链实现首次访问 ask、同域名 session 自动放行；`BuiltInMcpRegistry.isDisabled` 逻辑扩展为默认禁用 `chrome-devtools` MCP，除非显式启用 legacy 模式。

**Tech Stack:** TypeScript, Node.js 24, pnpm workspace, puppeteer-core, zod, vitest, picomatch.

> For executing workers: implement this plan task-by-task (prefer a fresh subagent/Task per task — a clean context per task avoids single-session degradation). Steps use - [ ] checkboxes for tracking.

## Risks & Open Questions

| # | Risk | Mitigation in plan |
|---|---|---|
| 1 | `puppeteer-core` 不自带 Chromium，无头环境/CI 中 `launch()` 失败 | `autoLaunch` 可配置为 `false`；连接模式优先；失败时返回明确错误消息 |
| 2 | macOS 上连接现有 Chrome 的 CDP 端口不稳定 | 支持显式 `chromePort` 配置；增加 `browserURL` 连接重试；保留 `legacyMcpEnabled` 回退 |
| 3 | 自动启动的 Chromium 无登录态，用户困惑 | 工具输出中标注 `handle.kind`；TUI 状态提示（后续迭代） |
| 4 | 按 host 授权过于粗放，子域名绕过 | 精确匹配 host，不支持通配符；`evil.kimi.com` 与 `kimi.com` 需分别授权 |
| 5 | 大页面快照 token 占用过高 | 默认截断文本至 8000 chars；截图默认非全屏；提供 `extract` schema 精确取数 |
| 6 | 与现有 `chrome-devtools` MCP 工具名冲突 | 原生工具使用 `Browser*` 前缀，与 `mcp__chrome-devtools__*` 不冲突 |
| 7 | `Agent` 类目前无 `close()` 生命周期，浏览器进程可能泄漏 | Task 15 在 `Session.close()` 中增加清理；`BrowserConnectionManager` 同时注册 `process.on('exit')` 钩子 |
| 8 | `BrowserAct` 自然语言指令解析不可靠 | Phase 1 优先使用 `selectors` 提示；自然语言解析作为 best-effort 兜底 |
