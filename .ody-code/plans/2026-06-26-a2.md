# Phase A2 — Cross-Language RPC Test Implementation Plan

**Goal:** Build a real TypeScript ↔ Rust cross-language RPC test that verifies `SDKRpcClient.connect` can spawn the release `ody-host` binary and exercise session lifecycle over stdio, Unix Domain Socket, and TCP.

**Architecture:** The TypeScript test harness resolves the release `ody-host` binary, spawns it through the existing `SDKRpcClient.connect` path, and asserts create/list/close session behavior across three transports. On the Rust side, `CoreHost::create_session` is extended to accept an optional `id` payload and route to the existing `SessionManager::create_with_id`. CI is made strict for the new cross-language test and failure logs are uploaded; the ADR records the prototype result and known limitations.

**Tech Stack:** TypeScript / Vitest (`packages/node-sdk`), Rust / tokio (`rust-ody/crates/ody-host`), GitHub Actions YAML, Markdown ADR.

## Risks & Open Questions

| Risk | Mitigation |
|---|---|
| TCP ports 19090–19099 may be in use on CI runners, causing `EADDRINUSE`. | Retry up to 10 ports; throw the original error if exhausted. If this proves flaky in practice, switch to dynamic port allocation in a follow-up. |
| UDS socket path exceeds macOS `sun_path` length (~104 bytes). | Use `os.tmpdir()` plus a short suffix; the test will fail with `ENAMETOOLONG` if the limit is hit. |
| `ody-host` process becomes a zombie if `client.close()` hangs. | `finally` block calls `client.close()` and then deletes `homeDir`; add a `setTimeout` + `SIGKILL` guard if needed. |
| Binary path resolution differs between local macOS and Linux CI. | Default path is derived from `import.meta.url`; override with `ODY_HOST_BINARY_PATH` env var. |
