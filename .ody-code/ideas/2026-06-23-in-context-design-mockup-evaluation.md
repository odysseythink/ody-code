# 想法质检报告 (Idea Evaluation Report)

**想法概述**：把设计模式的 mockup 从「独立组件预览」改成「嵌入到用户当前真实项目中的完整展示」，让用户能直观看到新增组件的最终落地效果。

> ⚠️ 说明：本次评估对象是一个**产品功能改进点**（而非独立创业想法），因此 `idea-evaluator` 框架中的市场规模、时机等维度会按「在 ody-code 产品内的价值」来适配解读。

## 排雷扫描

- **M1 SISP（拿方案找问题）**: ✅ Clear — 这条反馈是从真实使用体验出发的：独立 mockup 看不出来最终效果，用户需要额外想象，问题先于方案。
- **M2 Tar Pit（结构性死胡同）**: ✅ Clear — 这不是一个新赛道，而是对现有设计模式能力的增强，没有「很多人做过且失败」的结构性风险。
- **M3 Homework（没做功课）**: ⚠️ Partial — 反馈本身基于对当前 design mode 的观察，但缺少竞品对照数据（例如 Storybook、Figma Dev Mode 等是否已提供类似能力）。
- **M4 Idea Shopping（等待完美想法）**: ✅ Clear — 这是针对一个具体问题的具体改进方向，没有反复切换主题的迹象。

## 反直觉加分

- **S1 启动困难**: +1 — 要真正做到「把组件放进用户当前项目」需要不少脏活：解析项目结构、处理依赖、保证构建可运行、处理私有组件/样式等。高门槛也意味着竞争对手不容易抄。
- **S2 无聊领域**: +0 — 开发者工具不算特别「无聊」，竞争者并不少。
- **S3 已有竞品**: +1 — Storybook、Figma 等已经验证了「上下文预览」有价值，说明需求真实存在，不需要从零教育市场。

**调整后总分**: (15 + 2) / 2.3 = **7.4/10**

## 判定

🟢 **7.4/10 — 值得推进**

这是一个**高置信度的产品改进方向**：需求真实、已被竞品验证、可规模化、且有清晰的相邻探索空间。主要风险不在于「要不要做」，而在于「怎么以最小成本先验证真实项目上下文预览是否真的显著提升用户决策质量」。

## 下一步

建议走「48 小时轻量验证」路线：

1. **低保真原型**：先不接入真实项目构建，而是让用户手动指定一个本地项目路径/页面，把 mockup 渲染到该页面截图或简化 DOM 结构之上，快速看效果。
2. **找 3 个真实用户测试**：观察他们能否更快判断「这个组件放进去合不合适」。
3. **如果验证有效**，再投入做自动化项目上下文解析和实时预览。
4. **同时补竞品对照**：整理 Storybook / Figma Dev Mode / Chromatic 等工具的上下文预览做法，明确 ody-code 的差异化体验。
