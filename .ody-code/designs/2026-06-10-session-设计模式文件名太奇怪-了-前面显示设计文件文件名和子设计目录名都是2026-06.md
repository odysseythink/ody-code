# Fix: Session-Mode Filename Consistency

## Scope In

1. Remove eager filename resolution (`resolveFilePathEagerly`) from `SessionMode.enter()` [C:USER]
2. On first Write, derive the final filename from the model's requested path (basename slug), not from user-message topic extraction [C:USER]
3. Host still normalizes: adds date prefix, ensures `.ody-code/designs/` (or `.ody-code/plans/`), deduplicates against existing files [C:USER]
4. Update system prompt contract so the model is NOT told "host has ALREADY assigned the path"; instead it invents its own [C:USER]
5. Persist the resolved `_sessionModeFilePath` into `session_mode.enter` wire record so compaction replay restores it [C:INFERRED]

## Scope Out

- Changing the `extractTopicFromMessage` / `TopicGenerator` logic for non-session-mode use [C:DEFERRED]
- Changing the guard's writable-set rules (still only the assigned file + its `<stem>/` split subdirectory) [C:DEFERRED]
- Removing the date-prefix convention entirely [C:USER]

## Algorithms

### `resolveFilePathFromModelRequest`

```
function resolveFilePathFromModelRequest(requestedPath, content):
    if _sessionModeFilePath !== null:
        return _sessionModeFilePath

    dir ← resolveSessionModeDirectory(_kind).dir

    // Extract slug from model's requested path
    base ← basename(requestedPath)
    slug ← base
    if slug ends with '.md':
        slug ← slug without last 3 chars

    // Sanitize slug: lowercase, replace non-alphanum with '-', collapse
    slug ← slug.toLowerCase()
    slug ← slug.replace(/[^\p{L}\p{N}]+/gu, '-')
    slug ← slug.replace(/^-+|-+$/g, '')
    slug ← slug.replace(/-+/g, '-')

    if slug.length < 2:
        // Fallback to content heading extraction (existing logic)
        slug ← extractFirstHeading(content) ?? llmSummarizeTitle(content) ?? 'untitled'
        slug ← slugifyTitle(slug)

    datePrefix ← formatDatePrefix(new Date())
    stem ← `${datePrefix}-${slug}`
    finalStem ← await findUniqueStemInDir(dir, stem)
    path ← join(dir, `${finalStem}.md`)

    _sessionModeFilePath ← path
    emitStatusUpdated()

    // Persist to wire record
    records.logRecord({
        type: 'session_mode.enter',
        id: _sessionModeId,
        kind: _kind,
        path: path,
    })

    return path
```

### `restoreEnter` with path

```
function restoreEnter({ id, kind = 'plan', path }):
    replayBuilder.push({ type: 'session_mode_updated', enabled: true, kind })
    _isActive ← true
    _sessionModeId ← id
    _kind ← kind
    if path is provided and path.length > 0:
        _sessionModeFilePath ← path
    else:
        _sessionModeFilePath ← null
```

## Error & Degradation

| Error class | Trigger | Immediate handling | Degradation path | Recovery |
|---|---|---|---|---|
| `requestedPath` outside workspace | Model requests `/etc/passwd` | Write guard rejects with clear error | Model must choose path under cwd | Model retries with valid path |
| `slug` too short after sanitization | Model requests `.md` or `a.md` | Fallback to content heading / LLM / `untitled` | Filename may not reflect intent | Model can accept or clear+retry |
| `requestedPath` basename contains only non-alphanum | Model requests `---.md` | Same fallback chain | Same as above | Same as above |
| Legacy wire record lacks `path` | Old session replay | `restoreEnter` sets `_sessionModeFilePath = null` | First write re-resolves from model request | No user action needed |

## Self-Review

### Security
- Checked: `sanitizeSlug` regex `/[^\p{L}\p{N}]+/gu` for false positives/negatives. Confirmed it allows CJK characters (\p{L}) and digits (\p{N}), rejects path separators and special chars. No secrets/PII leak into filename because model's requested path is sanitized.
- Found & fixed: Initial draft did not consider that model might request path with embedded `../` — but `basename()` extracts only the final component, so directory traversal is blocked.

### Test
- Checked: Every behavior has must-pass and must-reject cases. Test #1 (path null after enter) and Test #6 (restore with path) are positive; Test #7 (legacy without path) is negative. Assertion in Test #2 uses regex that must match `YYYY-MM-DD-my-topic.md` — verified pattern `^.*\d{4}-\d{2}-\d{2}-my-topic\.md$` is correct.
- Found & fixed: Added Test #8 and #9 for injection footer behavior, ensuring the model sees correct guidance based on path availability.

### Ops
- Checked: Identifier collision on same-day sessions. `findUniqueStemInDir` with suffix counter handles this. No extra latency added (still synchronous basename extraction, async deduplication only on first write). Compaction replay now restores path, avoiding re-resolution.
- Found: Nothing to fix.

### Integration
- Verified: `records/types.ts` has `'session_mode.enter': { id: string; kind?: SessionModeKind }` — adding `path?: string` is a compatible extension. `records/index.ts:62-66` calls `restoreEnter` with `{id, kind}` — passing `path: input.path` works because `path` will be `undefined` for legacy records. All call sites verified with Read/Grep.
- Found & fixed: Confirmed `designModeEntryMessage` and `designModeFullReminder` in `design-mode-contract.ts` both use `withDesignFileFooter`, so changing the null-path message affects both entry and re-injection uniformly.

### Scope
- Checked: This design modifies a single subsystem (`SessionMode` filename resolution). It does NOT touch `TopicGenerator` (scope-out item), guard rules (scope-out item), or plan mode beyond shared `SessionMode` class. One coherent design, no decomposition needed.
- Found: Nothing to fix.
